# 蓝心同行最终产品人工验收分工

> 更新时间：2026-07-04  
> 目标：你和队友都以普通真实用户视角使用 Android 真机验收，覆盖 PRD 预期功能和比赛演示口径，避免重复劳动。发现问题后统一记录，后续交给 Codex 做整体修改。

## 验收原则

- 必须使用真机、真实模型、真实高德/工具数据和真实用户输入；Mock 或固定样例只能作为异常降级记录，不算通过。
- 两个人不要测同一条完整旅程。你使用“出行前到出行后主线”，队友使用“出行中增强与边界功能”。
- 每个问题都按“页面/步骤/输入/实际结果/期望结果/截图或录屏/严重程度”记录。
- 严重程度：S1 阻断演示；S2 影响主要体验；S3 文案、布局、动效、轻微不顺；S4 建议优化。
- 统一关注 ABCD：模型效果质量、App 流程顺滑、真实数据可信度、视觉与蓝小心角色感。

## 验收前准备

- 两台 Android/vivo 真机安装同一版本 APK。
- 后端使用真实 `.env` 启动，确认模型和高德 Key 可用。
- 连接同一网络，手机 API 地址指向可访问的后端地址。
- 准备可公开展示的照片素材 3-5 张，避免个人隐私、身份证明、未授权人像。
- 开始前清空或隔离历史测试数据，避免旧记忆影响判断。

## A 线：你负责的主线闭环

### A1 首页与蓝小心第一印象

- 从冷启动进入首页，观察蓝小心人物、状态卡、快捷入口、底部导航、首页直聊是否自然。
- 记录：是否像“旅行搭子”，文字是否清楚，按钮是否能理解，是否存在遮挡、重叠、卡顿。

### A2 角色化对话与记忆抽取

- 在首页或聊天页输入一条真实旅行需求，例如：`周末想去杭州两天，不想太累，喜欢夜景，我不吃香菜，预算别太高。`
- 检查蓝小心回复是否有陪伴感，不像普通客服。
- 检查是否抽取出可确认记忆：夜景、慢节奏、不吃香菜、预算偏好。
- 判断模型质量：
  - 通过：抽取内容准确、不过度保存隐私、能解释用途。
  - 不通过：漏掉关键偏好、误抽无关信息、语气生硬、没有蓝小心人格。

### A3 记忆确认与画像影响

- 对记忆分别选择长期/本次/临时/不记忆，至少确认 2 条长期记忆。
- 进入记忆页和画像相关入口，确认保存结果可见、可编辑、可删除。
- 重启 App 后再次查看，确认长期记忆仍存在。

### A4 个性化规划推理

- 进入行程页，用同一真实需求生成计划。
- 检查规划是否引用已确认画像，例如夜景、不吃香菜、慢节奏、预算。
- 检查真实数据可信度：
  - `toolTrace` 或页面说明应显示真实 provider，正常场景 `fallback=false`。
  - 天气、POI、路线、耗时、风险提示应和目的地基本匹配。
- 判断模型质量：
  - 通过：路线可执行，理由清楚，备选方案合理，风险提示具体。
  - 不通过：路线绕路、地点不真实、没有个性化理由、只是长文本攻略。

### A5 动态调整与主动提醒主线

- 触发一次“天气变化、排队过长、饭点、低精力、位置变化”中的任意真实或可演示场景。
- 检查蓝小心是否主动给出提醒，而不是只等用户提问。
- 采纳一次调整建议，观察行程是否更新、状态值是否变化。

### A6 旅行复盘

- 完成一次主线旅程后生成复盘。
- 检查复盘是否包含：今日路线、高光内容、新增记忆、状态变化、下次建议。
- 判断模型质量：
  - 通过：复盘能串起今天发生过的真实操作，不乱编固定景点。
  - 不通过：内容空泛、引用不存在照片/路线/任务、没有蓝小心陪伴感。

### A7 主线演示可用性结论

- 最后给出一句结论：是否能作为 3 分钟 Demo 主线。
- 列出最影响演示的前 5 个问题，按 S1/S2/S3 排序。

## B 线：队友负责的扩展与真实设备体验

### B1 旅拍候选集与真实照片

- 使用真机相册选择至少 2 张可公开照片，必要时用相机拍 1 张测试图。
- 检查候选登记是否明确说明不会上传本地路径或隐私信息。
- 生成朋友圈、小红书、日记、Vlog 旁白至少 3 类文案。
- 判断模型质量：
  - 通过：文案贴合照片内容、地点/情绪/风格，不像模板。
  - 不通过：识图错误、文案虚构过度、平台风格区分不明显。

### B2 旅行盲盒任务

- 获取盲盒任务，分别测试接受、跳过、完成。
- 完成后检查默契值/好感度/状态变化是否有反馈。
- 检查复盘中是否能看到完成的任务。

### B3 主动提醒与通知

- 在提醒页测试饭点、低精力、天气、位置或拍照行为触发。
- 验证系统通知权限和通知展示。
- 检查主动程度设置：安静/标准/活跃是否会影响触发频率。
- 常规体验不主动拒绝权限；拒绝路径另记为专项。

### B4 语音、TTS 与蓝小心表达

- 测试麦克风语音输入，观察中文识别是否可用、是否能回填到输入框。
- 测试蓝小心回复后的系统 TTS。
- 评价角色感：声音/语气/文本是否像同一个蓝小心。

### B5 设置、隐私与数据控制

- 检查设置页是否全中文、无开发接口路径或英文枚举暴露给普通用户。
- 测试主动程度、人格、语音/文字偏好等设置是否能保存。
- 测试导出记忆、选择性同步、撤销云端画像、本次旅行清空、全部记忆清空的确认流程。
- 检查危险操作是否有二次确认，文案是否清楚。

### B6 多设备与账号同步

- 使用第二台真机或独立会话验证游客/登录/游客升级。
- 新增一条记忆并同步，检查另一设备是否能看到。
- 制造一次记忆冲突，检查是否能看懂“本机/云端/覆盖/保留”的处理。
- 检查不同账号的数据不会串。

### B7 多人出游协调

- 输入至少 2 名成员偏好，例如一人想拍照、一人预算低、一人不想走太多路。
- 检查是否识别冲突并给出折中方案。
- 判断输出是否保护个人敏感偏好，不把队友隐私直接暴露成公开结论。

## 最终汇总方式

- 你汇总 A 线问题，队友汇总 B 线问题，不互相改对方结论。
- 汇总时每人最多列 10 个必须修改项，避免问题池失控。
- Codex 后续按严重程度处理：先 S1/S2，再 S3，S4 只在不影响主线时处理。
- 若某项需要人工配置、真实素材、账号权限或比赛平台操作，单独标注“人工介入”，不要混入代码问题。
